# Feature 4 Test Cases

| ID | กรณีทดสอบ | ขั้นตอนย่อ | ผลที่คาดหวัง |
|---|---|---|---|
| F4-01 | เปิดฟอร์มจากหน้ารายละเอียดสัตว์ | เปิด `/cases` เลือกเต้าหู้และกดขอรับเลี้ยง | ฟอร์มแสดงชื่อและประเภทสัตว์ถูกต้อง |
| F4-02 | ส่งคำขอด้วยข้อมูลครบ | กรอกทุกช่อง ยอมรับเงื่อนไข และส่ง | แสดงหน้าส่งสำเร็จและสร้างสถานะ `pending` |
| F4-03 | ไม่กรอกช่องบังคับ | เว้นชื่อหรือเบอร์โทรแล้วกดส่ง | Browser ระงับการส่งและชี้ช่องที่ต้องกรอก |
| F4-04 | เบอร์โทรผิดรูปแบบ | กรอกตัวอักษรในช่องเบอร์โทร | Browser ระงับการส่งคำขอ |
| F4-05 | เหตุผลสั้นเกินไป | กรอกเหตุผลน้อยกว่า 20 ตัวอักษร | Browser ระงับการส่งคำขอ |
| F4-06 | ยังไม่ยอมรับเงื่อนไข | กรอกครบแต่ไม่ติ๊กยืนยัน | Browser ระงับการส่งคำขอ |
| F4-07 | ดูคำขอของตนเอง | เปิด `/adoptions/my-requests` หลังส่งสำเร็จ | เห็นคำขอใหม่ วันที่ และสถานะรอพิจารณา |
| F4-08 | ผู้ใช้ไม่เห็นคำขอผู้อื่น | เข้าระบบด้วยผู้ใช้อีกบัญชี | RLS คืนเฉพาะรายการที่ `user_id` ตรงกับบัญชี |
| F4-09 | Admin กรองตามสถานะ | เปิด `/admin/adoptions` และเลือกแต่ละตัวกรอง | ตารางแสดงเฉพาะสถานะที่เลือก |
| F4-10 | Admin อนุมัติ | เปิดรายละเอียด กรอกหมายเหตุ และกดอนุมัติ | สถานะเป็น `approved` พร้อมเวลาและหมายเหตุ |
| F4-11 | Admin ไม่อนุมัติ | เปิดคำขอ pending แล้วกดไม่อนุมัติ | สถานะเป็น `rejected` และผู้ใช้เห็นหมายเหตุ |
| F4-12 | User พยายามแก้สถานะเอง | เรียก update ด้วย token ผู้ใช้ทั่วไป | Supabase RLS ปฏิเสธการแก้ไข |
| F4-13 | ไม่ได้เข้าสู่ระบบ | ตั้งค่า Supabase แล้วเปิดฟอร์มโดยไม่มี session | ระบบแจ้งให้เข้าสู่ระบบและไม่สร้างข้อมูล |
| F4-14 | ทดสอบ responsive | เปิดทั้ง 3 หน้าที่ 375px และ 1280px | ฟอร์ม การ์ด ตาราง และ modal ใช้งานได้โดยข้อมูลไม่ล้น |

## หลักฐานที่ควรเก็บ

- ภาพหน้าจอ F4-02, F4-07, F4-10 และ F4-11
- ภาพผล RLS หรือ network response ของ F4-08 และ F4-12
- ผลคำสั่ง `npm run lint` และ `npm run build`
